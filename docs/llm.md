# Подключение модели (LLM): рекомендация

## Коротко

- **Рекомендуемый вариант — Claude через Claude Code CLI**: `python -m poker.new … --llm claude`. Ключи API
  в проекте не нужны, используется ваша авторизация в Claude Code.
- Модель **не обязательна**. Без неё колода собирается детерминированно: факты из сигналов Jira и
  поведенческие вопросы из профиля роли.
- Модель **ничего не решает и не оценивает**. Она только ищет в комментариях наблюдаемые эпизоды для
  компетенций, где у сигналов нет данных. Это в первую очередь хард- и софт-навыки.
- Ответу модели **не доверяем**. Эпизод проходит в колоду, только если компетенция есть в профиле, ключи задач
  есть в выгрузке, а цитата дословно встречается в комментарии сотрудника. Всё остальное отбрасывается.

## Зачем модель нужна

Сигналы Jira хорошо видят дисциплину: сроки, переходы, нагрузку, делегирование. Но они не понимают
**содержание** работы. Например, что аналитик сам сузил скоуп, разрулил спор со смежниками или дал разработке
чистый хендофф. Это читается только из текста комментариев. Модель находит такие эпизоды и превращает
поведенческий вопрос по компетенции в карту с фактом.

## Как подключить Claude (рекомендуется)

1. Установите и авторизуйте Claude Code: `claude --version`, затем `claude` → вход.
2. Создайте встречу с флагом:
   ```bash
   uv run --with requests python -m poker.new --login jdoe --from 2026-09-01 --to 2026-09-30 --llm claude
   ```
3. Модель по умолчанию — та, что настроена в Claude Code. Выбрать явно можно так: `--model sonnet` или `--model opus`.

### Какую модель выбрать

| Модель | Когда | Почему |
|---|---|---|
| **Claude Sonnet** (`--model sonnet`) — рекомендуется | обычная подготовка | быстро и недорого, хорошо держит русский и строгий JSON. Задача — извлечение, а не рассуждение |
| Claude Opus (`--model opus`) | много длинных обсуждений, сложная предметка | лучше различает тонкие эпизоды (позиция в споре, качество аргументации), но медленнее и дороже |
| Claude Haiku (`--model haiku`) | очень большие выгрузки, пробные прогоны | самый быстрый; эпизодов найдёт меньше |

В отчёте после `poker.new` видно, сколько эпизодов модель предложила и сколько отбросила проверка. Если
отбрасывается больше половины, переходите на модель мощнее.

## Что уходит в модель

`poker/llm.py` → `compact_activity()` отправляет:

- список компетенций роли: id, название, описание, где искать;
- по задачам: ключ, тему, **комментарии сотрудника** (до 600 символов каждый, до 5 на задачу) и его переходы статусов.

Не отправляется:
- имя сотрудника и роль руководителя;
- чужие комментарии;
- ворклоги;
- поля-роли;
- досье.

Упоминания вида `[~login]` заменяются на «@коллега».

**Важно:** текст комментариев уходит как есть. Если в нём упомянуты люди по имени, системы или данные
заказчика, они попадут к провайдеру модели.

## Что согласовать в компании

Комментарии Jira — рабочие данные, а сама колода касается оценки конкретного человека. Перед использованием:

1. **Информационная безопасность.** Можно ли передавать текст комментариев Jira внешнему провайдеру LLM.
   Проверьте условия вашего тарифа или договора с Anthropic: хранение данных, обучение на данных, регион.
2. **HR или юристы.** Использование автоматической обработки при подготовке беседы о работе сотрудника. Модель
   только подбирает факты, оценку ставят люди. Это стоит прямо сказать сотруднику на экране правил.
3. Если согласования нет, работайте без `--llm`. Колода останется полноценной: факты из сигналов и
   поведенческие вопросы.

## Другие варианты подключения

Команду вызова модели можно заменить переменной `POKER_LLM_CMD`. Команда получает промпт в stdin и
печатает ответ в stdout:

| Вариант | `POKER_LLM_CMD` | Когда |
|---|---|---|
| Claude Code CLI (по умолчанию) | не задавать | есть Claude Code |
| Anthropic API напрямую | `python3 scripts/llm_anthropic.py` (нужны `pip install anthropic` и `ANTHROPIC_API_KEY`) | сервер без Claude Code, корпоративный ключ API |
| Своя обёртка или шлюз | `/путь/к/скрипту` | корпоративный LLM-шлюз, другая модель |

## Как это устроено

```
activity (в памяти) ─▶ prompts/llm-evidence.md + compact_activity() ─▶ claude -p
        ▲                                                                  │
        └──── validate(): компетенция ∈ профиль, ключи ∈ выгрузка, ◀───────┘
              цитата ∈ комментарий, ≤ 1 эпизода на компетенцию, ≤ 8 всего
                         │
                         ▼
              карта-факт вместо поведенческой ─▶ печать колоды
```

- Промпт — `prompts/llm-evidence.md`. Его можно править, формат ответа (JSON-массив) менять нельзя.
- Ответ разбирается устойчиво к ```json-фенсам и тексту вокруг.
- Если модель недоступна (нет CLI, таймаут, ошибка), колода собирается без неё, и об этом пишется в отчёте.
- Результат модели сразу уходит под печать: руководитель его не видит, как и остальные карты.

## Claude Code как помощник руководителя

Скилл `/poker` (`.claude/skills/poker/SKILL.md`) запускает `poker.new` из Claude Code. В скилле зашито правило:
**не открывать и не пересказывать содержимое колоды и выгрузки до встречи**. Claude видит только
отчёт без содержания и ссылки. Так сохраняется требование «руководитель не видит карт заранее», даже когда
готовит встречу через Claude.
