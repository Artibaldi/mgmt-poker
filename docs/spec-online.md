# Онлайн-сессия: пользовательский путь, протокол и модель доверия

Описывает режим, в котором руководитель и сотрудник играют **одновременно, каждый на своём экране**, по ВКС под
запись. Офлайн-режим на одном экране (`poker.build` → `game.html`) остаётся запасным.

## Требования

1. Встреча онлайн, под запись. Оба оценивают одновременно и **не видят оценку визави до вскрытия**.
2. **Карт до встречи не видит никто**, в том числе руководитель. Он задаёт только человека и период.
3. Карты строятся по модели компетенций: хард по должности, софт, личные качества, управленческие
   ([competencies.md](competencies.md)).
4. После встречи **сотрудник** выгружает свои ответы и ответы руководителя.
5. Развёртывание у руководителя локально; VPN может быть, а может и не быть ([deploy-local.md](deploy-local.md)).

## Пользовательский путь

```
РУКОВОДИТЕЛЬ                        СИСТЕМА                                   СОТРУДНИК
poker.new --login --from --to  ─▶  выгрузка Jira → сигналы → (Claude)
                                    → колода по профилю роли → автопроверка
                                    → печать (ключ = половина₁ ⊕ половина₂)
видит отчёт без содержания     ◀─  две ссылки
отправляет ссылку с приглашением ──────────────────────────────────────────▶ получает ссылку
ВКС с записью · открывает свою ссылку                                        открывает свою ссылку
                       ЛОББИ: оба в комнате → колода открывается у обоих одновременно
                       РАМКА: правила, шкала, «ВКС записывается» → оба «Готов»
                       РАУНД × N: прочитал / факт неточен → оценка + «почему» (печать)
                                  → вскрытие → разговор → договорённость (подтверждают оба)
                       ИТОГИ: оба «Итоги верны» → руководитель «Закрыть встречу»
results.md / results.json  ◀─────  итоги                 ─────────────────▶ «Выгрузить .md / PDF»
следующая колода начнётся с проверки договорённостей
```

### Кто что видит

| Данные | До встречи | На встрече | В выгрузке |
|---|---|---|---|
| Карты (факты, вопросы, якоря) | никто: колода запечатана | оба, одновременно | оба |
| Оценка и «почему» второго игрока | — | только после вскрытия | оба |
| «Что показывают данные» | никто | после вскрытия | оба |
| Сырая выгрузка Jira | ноутбук руководителя, в зашифрованном виде | — | — |
| Договорённости | — | оба, каждую подтверждают оба | оба + следующая колода |

### Роли за столом

| Действие | Руководитель (host) | Сотрудник (guest) |
|---|---|---|
| Отметить начало записи ВКС | ✅ | — |
| Листать карты, к итогам | ✅ | просит «вернуться» |
| Пауза | — | ✅ |
| Снять карту | ✅ | — |
| Прочитал / факт неточен, оценка, договорённость | ✅ | ✅ |
| Подтвердить итоги | ✅ | ✅ |
| Закрыть встречу | ✅ после двух подтверждений | — |
| Выгрузить итоги | ✅ | ✅ |

## Протокол

Комната — журнал событий (`room-log.jsonl`), который ретранслятор (`poker/relay.py`) принимает, проверяет и
раздаёт обоим. Состояние у каждого браузера считается одной и той же функцией `reduce()` (`poker/web/core.js`)
из одного и того же журнала, поэтому экраны синхронны.

| Событие | Кто | Проверка на ретрансляторе |
|---|---|---|
| `hello {name, half}` | оба | половину ключа нельзя подменить повторным входом |
| `ready`, `read {card, flag?, text?}` | оба | — |
| `commit {card, hash}` | оба | один раз на карту; hash = SHA-256(card‖role‖vote‖salt‖why) |
| `reveal {card, vote, why, salt}` | оба | только когда положены обе печати; значение обязано совпасть с печатью |
| `draft {card, text, owner, due}`, `agree {card, draft}` | оба | новый черновик сбрасывает согласия |
| `rec`, `nav`, `drop`, `export`, `close` | руководитель | `close` — только после двух `summary_ok` и `export` |
| `pause`, `back`, `summary_ok` | оба | — |

**Слепая оценка (commit–reveal).** Браузер отправляет только печать оценки. Сама оценка и «почему» хранятся
локально, пока обе печати не лягут. После этого каждый браузер раскрывает свою, а ретранслятор и второй браузер сверяют
её с печатью. До вскрытия значения нет ни на сервере, ни у второго игрока. Поэтому даже руководитель, у
которого работает ретранслятор, не может подсмотреть оценку сотрудника.

**Печать колоды.** Ключ K = K₁ ⊕ K₂. Половины лежат в ссылках после `#` и на сервер с запросом не уходят.
Колода хранится и отдаётся только зашифрованной (SHA-256-CTR + HMAC-SHA256, `poker/seal.py` ↔ `core.js`).
Браузеры собирают ключ, когда в журнале есть `hello` обоих, и время вскрытия попадает в итоги. Шифрование
реализовано без WebCrypto, поэтому работает по http внутри VPN.

**Таймкоды.** Время каждого вскрытия отсчитывается от `rec`, то есть от момента, когда руководитель отметил
начало записи ВКС. Так по записи легко найти разговор по нужной карте.

## Модель доверия: что гарантируется, а что нет

| Угроза | Защита |
|---|---|
| Один игрок видит оценку другого до вскрытия | commit–reveal: значения нет нигде до двух печатей |
| Игрок меняет оценку после того, как увидел чужую | печать неизменна; раскрытие проверяется по ней на сервере и у второго игрока |
| Руководитель читает карты заранее по своей ссылке | одной половины ключа мало |
| Колоду случайно открыли или переслали файлом | файл зашифрован, ключ только в ссылках |
| Сотрудник выдаёт себя за ведущего | токены ролей разные, действия ведущего проверяются на сервере |

Чего печать **не** гарантирует, и это честно стоит проговорить:

- Руководитель запускает генератор и отправляет ссылку сотрудника, поэтому технически у него в руках обе
  половины ключа (`links.txt`). Печать защищает **процесс**: заглянуть заранее можно только намеренно, а
  время вскрытия колоды фиксируется в итогах.
- Руководитель — владелец данных Jira и может посмотреть задачи напрямую. Это не утечка, а исходные данные.
- Вне VPN трафик по http не зашифрован: после вскрытия оценки и договорённости идут открытым текстом. Для
  работы вне VPN нужен HTTPS ([deploy-local.md](deploy-local.md#если-vpn-нет)).

## Хранение

`sessions/<login>_<YYYY-MM>/`, в git не попадает:

| Файл | Что | Когда |
|---|---|---|
| `room.json` | id комнаты, хеши токенов, срок жизни | `poker.new` |
| `deck.sealed.json`, `activity.sealed.json` | колода и выгрузка, зашифрованные | `poker.new` |
| `links.txt` | ссылки руководителя и сотрудника | `poker.new` |
| `room-log.jsonl` | журнал событий встречи | во время встречи |
| `results.md`, `results.json` | итоги; json — для следующей колоды (покрытые компетенции и договорённости) | при закрытии |
