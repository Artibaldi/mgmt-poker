# Модель компетенций

Колода собирается автоматически из модели компетенций роли. Руководитель задаёт только человека и период, а роль берётся из `config/team.json`.

## Четыре масти = четыре группы навыков

| Масть | Группа | Откуда компетенции |
|---|---|---|
| ♠ | Профессиональные навыки (хард) | свои у каждой роли: `competencies/roles/<роль>.json` → `hard` |
| ♦ | Софт-навыки | общие: `competencies/common.json` |
| ♣ | Личные качества и самоорганизация | общие |
| ♥ | Управленческие навыки | общие; у ролей без подчинённых — в основном «лидерство без полномочий» |

У каждой компетенции есть:
- описание;
- **якоря** — как выглядит поведение на уровнях 1 · 2 · 3 · 5 · 8 (за столом их видят оба игрока);
- сигналы Jira, которые могут её подтвердить;
- подсказка, где искать следы;
- вопрос для оценки и 2–3 вопроса для разговора в формате STAR.

## Шкала

| Уровень | Смысл |
|---|---|
| 1 | не проявлено |
| 2 | эпизодически |
| 3 | проявлено |
| 5 | устойчиво |
| 8 | образцово, задаёт стандарт другим |
| ? | не знаю — нужен разговор |

## Как собирается колода (`poker/deck.py`)

1. **Компетенции роли:** все хард-навыки (вес 3) и общие с весом больше 0.
2. **Доказательства за период:**
   - сигналы Jira (`poker/signals.py`), каждый сигнал достаётся одной компетенции;
   - при `--llm claude` — проверенные эпизоды из комментариев ([llm.md](llm.md)).
3. **Места по мастям:** 12 карт, минимум одна на масть, остальное — пропорционально сумме весов масти.
4. **Выбор внутри масти:**
   - выше те, у кого есть доказательства за период;
   - выше те, что не обсуждали на двух прошлых встречах;
   - дальше — по весу; при равенстве — детерминированная ротация по периоду.
5. **Тип карты:**
   - есть доказательство → **факт из Jira** (с ключами задач и «что показывают данные»);
   - нет → **поведенческий вопрос** с якорями;
   - до двух договорённостей прошлой встречи → **проверка договорённости**, первыми.
6. **Автопроверка (`sanitize`):** ключи из выгрузки, нет оценочных слов, колода не уже 4 карт и 2 мастей. Непрошедший факт становится поведенческим вопросом.
7. **Печать:** колода сразу шифруется; руководитель видит только отчёт без содержания.

## Как изменить модель

- **Поправить якоря или вопросы** — правьте JSON и запустите `scripts/test.sh`: тест проверит структуру.
- **Добавить роль** — новый `competencies/roles/<id>.json` по образцу: 5 хард-навыков с префиксом роли и `weights` по всем 18 общим id.
- **Добавить общую компетенцию** — в `common.json`, затем вес для неё во **всех** ролях (иначе тест упадёт).
- **Связать с сигналом** — id сигнала в `signals` компетенции; список сигналов — [jira-integration.md](jira-integration.md).
