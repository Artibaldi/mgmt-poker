# /poker <jira-login> <YYYY-MM | from..to> [--llm]

Путь и протокол — `docs/spec-online.md`, развёртывание — `docs/deploy-local.md`, модель — `docs/llm.md`.

## Главное правило
**Карт до встречи не видит никто, включая руководителя и тебя.** Не открывай и не читай:
`deck.sealed.json`, `activity.sealed.json`, `links.txt` (только передай пути), `room-log.jsonl`,
и не расшифровывай их. Не пересказывай содержание выгрузки Jira. Показываешь только отчёт `poker.new`
без содержания карт и ссылки, которые он напечатал.

## Шаги
1. **Период:** `2026-09` → `--from 2026-09-01 --to 2026-09-30`.
2. **Роль и имя:** из `config/team.json`. Если человека там нет, спроси роль
   (system-analyst, business-analyst, developer, qa, devops, architect, project-manager, team-lead)
   и имя для карточек. Сам роль не придумывай.
3. **Модель:** `--llm claude` — только если пользователь согласен передавать комментарии Jira в Claude
   (docs/llm.md, «что согласовать»). По умолчанию без неё.
4. **Создать встречу:**
   `uv run --with requests python -m poker.new --login <login> --from … --to … [--llm claude --model sonnet]`
   Креды — `.env` или `$POKER_ENV`. «0 задач» в отчёте почти всегда означает не тот логин: скажи об этом.
5. **Комната:** проверь `curl -s localhost:8765/health`. Если не отвечает, предложи запустить
   `python3 -m poker.relay` в отдельном терминале (`! python3 -m poker.relay`) или через launchd (docs/deploy-local.md).
6. **Отдай пользователю:** отчёт и обе ссылки как напечатал `poker.new`. Напомни: ссылку сотрудника
   отправлять целиком, вместе с частью после `#`, в приглашении на ВКС; свою ссылку не пересылать.

## После встречи
Итоги — `sessions/<login>_<YYYY-MM>/results.md`. Их можно прочитать и обсудить с пользователем: встреча
уже прошла, итоги принадлежат обоим участникам.

## Гардрейлы
- Всё о человеке — только в `sessions/` (под .gitignore). Перед коммитом `git status --porcelain sessions/` пуст.
- Ничего не писать в Jira и Confluence. Артефакты claude.ai с данными людей не создавать.
