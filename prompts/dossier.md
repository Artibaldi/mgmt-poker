## Промт

Ты готовишь досье для 1:1 в формате «Управленческий покер» (метод — docs/method.md).

**Вход:**
- `activity.json` — действия человека в Jira за период (его комментарии, переходы, правки полей, ворклоги);
- `signals.md` — автоматические сигналы (гипотезы, не оценки);
- саммари встреч за период, где упомянут человек (если есть);
- роль человека и с кем он работает (от руководителя).

**Сделай файл `dossier.md`:**

1. Шапка: роль, команда/смежники, источники (пути к файлам, число задач/комментариев/переходов).
2. Таблица эпизодов `# | Дата | Источник | Факт | Компетенция | Оценка`, 10–16 строк.
   - Факт — наблюдаемое действие, без оценочных слов, с конкретикой (что, кому, какой срок).
   - Источник — ключ задачи + тип следа (комментарий/changelog) или имя саммари встречи.
   - Оценка — `Проявил` / `Не проявил` / `Спорно` (+ короткое пояснение при «спорно»).
   - Каждый сигнал из `signals.md` проверь по задачам: подтвердился — эпизод, нет — не включай.
3. «Слепые зоны» — 2–4 пункта, чего в данных не видно (развитие людей, ёмкость, хвосты, право эскалации).
4. «Профиль (гипотеза до игры)»: **Сильное**, **Слабое**, **Риск** — по 2–4 пункта, со ссылками на эпизоды.

**Правила:** только факты из входных данных, ничего не додумывать; если источник неясен — не включать;
сильных эпизодов не меньше, чем слабых; не путать однофамильцев и тёзок (сверять логин Jira).
Пометка в начале: «Рабочий материал для игры. Не публиковать, не постить в Jira/Confluence.»
